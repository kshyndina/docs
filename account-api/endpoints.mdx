---
title: "Endpoints API: Create and Manage RPC Endpoints"
sidebarTitle: "Endpoints"
description: "Provision and manage Triton One RPC endpoint URLs. Endpoints belong to subscriptions and support both token-based and allowed-origin access for clients."
---

An endpoint is the URL your clients call to consume the Solana RPC. Each endpoint belongs to a subscription, inherits the network environment of its subscription type, and is assigned a rate tier that determines its cost and throughput limits. When an endpoint is created, Triton assigns it a unique slug, and the final hostnames your clients connect to are derived from that slug — they appear in the `values` array on the endpoint object.

Endpoints support two access patterns: token-based access (for backend services) and allowed-origins access (for frontends that cannot safely embed a token). You can configure both on the same endpoint.

Creating, activating, and deactivating endpoints requires a **Reseller** role token. Listing endpoints and updating allowed origins are available to Operator and Reseller tokens.

---

## List endpoints

`GET /api/v1/endpoints`

Returns all endpoints accessible to your token. You must provide either `account_uuid` or `subscription_uuid` as a filter — the request will fail without one.

### Query parameters

<ParamField query="account_uuid" type="string">
  Return endpoints belonging to this account. Required if `subscription_uuid` is not provided.
</ParamField>

<ParamField query="subscription_uuid" type="string">
  Return endpoints belonging to this subscription. Required if `account_uuid` is not provided.
</ParamField>

<Note>
  You must provide at least one of `account_uuid` or `subscription_uuid`.
</Note>

### Request

<CodeGroup>

```bash Filter by account
curl 'https://customers.triton.one/api/v1/endpoints?account_uuid=c92a9cea-47cc-494b-b1b0-4230a2316ee5' \
  -H "Authorization: secret-api-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json"
```

```bash Filter by subscription
curl 'https://customers.triton.one/api/v1/endpoints?subscription_uuid=74ea9d9a-4b2a-4f01-af47-1c175f8a2af6' \
  -H "Authorization: secret-api-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json"
```

</CodeGroup>

## Create an endpoint

`POST /api/v1/subscriptions/:subscription_uuid/endpoints`

<Warning>
  This endpoint requires a **Reseller** role token.
</Warning>

Creates a new endpoint under the given subscription. The endpoint is created in an inactive state — call the activate endpoint to enable it for traffic.

### Path parameters

<ParamField path="subscription_uuid" type="string" required>
  UUID of the subscription the endpoint will belong to.
</ParamField>

### Body parameters

Wrap all parameters inside an `endpoint` key.

<ParamField body="name" type="string" required>
  Human-readable name for the endpoint.
</ParamField>

<ParamField body="rate_tier" type="string" required>
  Name of the rate tier to assign to this endpoint. Determines cost and rate limits. Use `GET /api/v1/rate_tiers` to see available options.
</ParamField>

<ParamField body="allowed_origins" type="object[]">
  Array of DNS CNAME objects for frontend origins that can call this endpoint without a token. All new entries are automatically enabled. Each object takes the form `{"value": "example.com"}`.
</ParamField>

### Request

```bash
curl -X POST 'https://customers.triton.one/api/v1/subscriptions/74ea9d9a-4b2a-4f01-af47-1c175f8a2af6/endpoints' \
  -H "Authorization: secret-api-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "endpoint": {
      "name": "Endpoint 123",
      "rate_tier": "developer",
      "allowed_origins": [
        { "value": "example.com" },
        { "value": "frontend.website.com" }
      ]
    }
  }'
```

### Response

Returns the created `endpoint` object. Note that `is_active` is `false` until you explicitly activate the endpoint.

<ResponseField name="endpoint" type="object">
  <Expandable title="properties">
    <ResponseField name="uuid" type="string">Generated UUID for the new endpoint.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="slug" type="string">URL-safe identifier used in the endpoint hostnames.</ResponseField>
    <ResponseField name="rate_tier" type="string">Assigned rate tier name.</ResponseField>
    <ResponseField name="is_active" type="boolean">Always `false` on creation. Activate separately.</ResponseField>
    <ResponseField name="values" type="string[]">Hostnames clients use to call this endpoint.</ResponseField>
    <ResponseField name="default_values" type="string[]">Default hostnames for this endpoint.</ResponseField>
    <ResponseField name="allowed_origins" type="object[]">Configured allowed origins, each with `uuid`, `value`, and `is_active`.</ResponseField>
    <ResponseField name="deactivation_reasons" type="object[]">Empty on a newly created endpoint.</ResponseField>
  </Expandable>
</ResponseField>

## Update an endpoint

`PUT /api/v1/endpoints/:endpoint_uuid`

Updates a endpoint's name, rate tier, or allowed origins. The `allowed_origins` update is a **full replacement** — the list you pass overwrites all existing allowed origins. To remove an origin, omit it from the array. To keep an existing origin, include it with its current value.

Updating `rate_tier` requires a **Reseller** role token. Standard role tokens can update `name` and `allowed_origins`, but are limited to one allowed origin.

### Path parameters

<ParamField path="endpoint_uuid" type="string" required>
  UUID of the endpoint to update.
</ParamField>

### Body parameters

<ParamField body="name" type="string">
  Updated display name.
</ParamField>

<ParamField body="rate_tier" type="string">
  Updated rate tier name. Reseller role only.
</ParamField>

<ParamField body="allowed_origins" type="object[]">
  Full replacement list of allowed origins. Each object takes the form `{"value": "example.com", "is_active": true}`. Standard role tokens are limited to one entry.
</ParamField>

### Request

```bash
curl -X PUT 'https://customers.triton.one/api/v1/endpoints/74ea9d9a-4b2a-4f01-af47-1c175f8a2af6' \
  -H "Authorization: secret-api-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "endpoint": {
      "name": "Endpoint 123",
      "rate_tier": "developer",
      "allowed_origins": [
        { "value": "example.com", "is_active": true },
        { "value": "frontend.website.com", "is_active": true }
      ]
    }
  }'
```

### Response

```json

    "uuid": "6ec86e74-783b-4779-b626-937a5c1e2a89",
    "name": "New Endpoint Name",
    "value": null,

    "rate_tier": "developer",
    "is_active": false,
    "value_override": null,
    "values": [
      "tylerqt-example-f988.TEST 1",
      "tylerqt-example-f988.TWST 2",
      "tylerqt-example-f988.value-3"
    ],
    "default_values": [
      "tylerqt-example-f988.TEST 1",
      "tylerqt-example-f988.TWST 2",
      "tylerqt-example-f988.value-3"
    ],
    "allowed_origins": [
      {
        "uuid": "32d511f0-3fb0-4570-8922-f8bc988b41a1",
        "value": "example.com",
        "is_active": true
      }
    ],
    "deactivation_reasons": [
      {
        "description": "Deactivation reason description",

}
```

## Activate an endpoint

`PUT /api/v1/endpoints/:endpoint_uuid/activate`

<Warning>
  This endpoint requires a **Reseller** role token.
</Warning>

Activates an endpoint so it can accept RPC traffic.

### Path parameters

<ParamField path="endpoint_uuid" type="string" required>
  UUID of the endpoint to activate.
</ParamField>

### Request

```bash
curl -X PUT 'https://customers.triton.one/api/v1/endpoints/74ea9d9a-4b2a-4f01-af47-1c175f8a2af6/activate' \
  -H "Authorization: secret-api-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json"
```

### Response

```
204 No Content
```

## Deactivate an endpoint

`PUT /api/v1/endpoints/:endpoint_uuid/deactivate`

<Warning>
  This endpoint requires a **Reseller** role token.
</Warning>

Deactivates an endpoint so it no longer accepts RPC traffic. You can optionally record a reason.

### Path parameters

<ParamField path="endpoint_uuid" type="string" required>
  UUID of the endpoint to deactivate.
</ParamField>

### Body parameters

<ParamField body="deactivation_reason" type="string">
  Human-readable explanation for the deactivation.
</ParamField>

### Request

```bash
curl -X PUT 'https://customers.triton.one/api/v1/endpoints/74ea9d9a-4b2a-4f01-af47-1c175f8a2af6/deactivate' \
  -H "Authorization: secret-api-token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "deactivation_reason": "Deactivation reason description"
  }'
```

### Response

```
204 No Content
```

<Tip>
  Use `allowed_origins` when you need a browser-based frontend to call an RPC endpoint directly without embedding a secret token. Set each entry to the DNS CNAME of your frontend (e.g. `"app.example.com"`). Traffic from any unlisted origin still requires a valid token.
</Tip>
