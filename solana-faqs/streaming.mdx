## Project Yellowstone

What is Yellowstone and which subscriptions include streaming access?

<AccordionGroup>
  <FaqWhatIsYellowstone />

  <Accordion title="How can I install Yellowstone on my server?">
    You don't need to install anything. All Geyser streaming products (Dragon's Mouth, Whirligig) are pre-installed on Triton infrastructure and enabled automatically for all subscriptions.
  </Accordion>

  <Accordion title="Is Geyser streaming available with all subscriptions?">
    Yes. All subscriptions include Geyser streaming by default, with no setup required. It's available as soon as your subscription is active.
  </Accordion>
</AccordionGroup>

## Yellowstone components

The questions about streaming products built on Yellowstone.

<AccordionGroup>
  <Accordion title="What is the maximum number of accounts I can subscribe to using Yellowstone gRPC?">
    For shared plans, the current limit is ~150,000 account subscriptions per HTTP connection.

    For dedicated nodes, there's no set limit. However, opening too many subscriptions for your servers to ingest can cause backpressure from your backend, leading to poor streaming performance. Please check that your server can handle the amount of data you are subscribing to.
  </Accordion>

  <Accordion title="What is Steamboat, and how does it improve latency?">
    Steamboat is Triton's custom program indexer within Project Yellowstone. By pre-indexing Solana program accounts, `getProgramAccounts` queries are accelerated by up to 400ms compared to unindexed calls.

    Cascade, Fumarole, Vixen Streams, and custom indexes for Steamboat are add-ons that we can activate for you upon request.

    If you want to run these on your own nodes, they're open source.
  </Accordion>

  <Accordion title="What is Fumarole, and how can I get access?">
    Fumarole is a new streaming system designed for reliable and scalable streaming of account and transaction data. It aggregates data from multiple downstream Solana nodes to ensure high availability and data persistence with up to 4 days of retained stream history. Additionally, Fumarole supports horizontal scalability by allowing data to be managed across multiple readers using consumer groups.

    Please note that Fumarole is currently in limited beta, and access is managed through Triton's CS channel.
  </Accordion>

  <Accordion title="What is Cascade Marketplace?">
    Cascade is a stake-weighted bandwidth marketplace for Solana. It allows validators to sell their SWQoS transaction capacity and lets consumers buy predictable, reserved bandwidth for priority delivery during network congestion.
  </Accordion>
</AccordionGroup>

## gRPC and WebSocket

Connecting to streaming services from backend code, browsers, or via Geyser plugins.

<AccordionGroup>
  <Accordion title="Can I use gRPC from a web browser?">
    No, gRPC is not supported in web browsers due to HTTP/2 and protobuf limitations. It is designed for backend applications. For frontend use, try Whirligig WebSockets instead.
  </Accordion>

  <Accordion title="Do endpoints support WebSocket connections?">
    Yes. We support both standard WebSockets and Whirligig, our optimised, high-performance implementation, on both shared and dedicated infrastructures.

    We recommend using Whirligig for better stability and throughput.
  </Accordion>

  <Accordion title="How do I connect to WebSockets?">
    Simply replace `https` with `wss` in your RPC endpoint URL. For example: `wss://your-endpoint.rpcpool.com`. We do recommend, however, using the gRPC interface for streaming purposes if available -- see the [Dragon's Mouth gRPC](/solana/streaming/dragons-mouth-g-rpc) page for details on how to do that on Solana.
  </Accordion>

  <Accordion title="How can I use Geyser plugins?">
    Geyser plugins can be enabled on our dedicated Solana nodes. They provide powerful, real-time streams of on-chain data. Contact our support team to discuss your specific needs and we can configure a node for you.
  </Accordion>

  <Accordion title="I keep getting errors on my gRPC subscription. How can I check if the issue is with my endpoint or my code?">
    Run our prebuilt `client-ubuntu` test client. It's a small Linux CLI we ship for exactly this purpose -- known-good code that hits your endpoint with the same gRPC subscription patterns your app does. If it errors, the issue is on the endpoint and we should look at it. If it streams cleanly, the issue is in your application code.

    Full guide: [Verify your gRPC endpoint](/solana-guides/error-handling/verify-grpc-endpoint).
  </Accordion>
</AccordionGroup>
