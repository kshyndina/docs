Test out any Triton streaming service in five minutes. For the full overview and product comparison, see the [streaming overview](/solana/streaming/overview).

## Prerequisites

All four services use Triton-issued endpoints with token-based authentication. Before starting:

- An active Triton subscription
- Your endpoint URL and secret token from the [customer dashboard](https://customers.triton.one/) ([how to get them](/solana/get-started/account-management/set-up-your-account-and-add-users))
- A backend environment in TypeScript, Rust, Go, or Python
- You've picked a service to try (skim the cards below)

<CardGroup cols={2}>
  <Card title="Dragon's Mouth gRPC" icon="radio" href="/solana/streaming/dragons-mouth/overview">

  <Card title="Whirligig WebSocket" icon="rotate-cw" href="/solana/streaming/whirligig/overview">

<Steps>
  <Step title="Install">
    Dragon's Mouth, Fumarole, and Old Faithful streams share the same `yellowstone-grpc` client across languages. Fumarole adds a small client on top for persistent-subscriber management. Whirligig works with any standard WebSocket client and doesn't need a Triton-specific SDK.

    <Tabs>
      <Tab title="TypeScript">
        ```bash
        npm install @triton-one/yellowstone-grpc

        # For Fumarole specifically:
        npm install @triton-one/yellowstone-fumarole-client

        # For Whirligig (any WebSocket library works):
        npm install ws
        ```
      </Tab>
      <Tab title="Rust">
        ```toml
        [dependencies]
        yellowstone-grpc-client = "1.13.0"
        yellowstone-grpc-proto = "1.13.0"
        # For Fumarole:
        yellowstone-fumarole-client = "0.5"
        tokio = { version = "1", features = ["full"] }
        futures = "0.3"
        ```
      </Tab>
      <Tab title="Go">
        ```bash
        go get github.com/rpcpool/yellowstone-grpc/examples/golang@latest
        go get google.golang.org/grpc@v1.67.1
        ```
      </Tab>
      <Tab title="Python">
        ```bash
        pip install grpcio grpcio-tools

        # Yellowstone proto bindings via the official examples repo:
        git clone https://github.com/rpcpool/yellowstone-grpc.git
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Connect and subscribe">
    Each tab shows minimal TypeScript code to connect, subscribe, and read events. For Rust, Go, and Python examples, follow the link below each block.

    <Tabs>
      <Tab title="Dragon's Mouth">
        Connect over gRPC, subscribe to all token-program account updates, log each event.

        ```typescript
        import Client, { CommitmentLevel } from "@triton-one/yellowstone-grpc";

        const client = new Client(
          "https://<your-endpoint>.mainnet.rpcpool.com",
          "<your-token>",
          undefined
        );

        const stream = await client.subscribe();

        stream.on("data", (data) => {
          console.log("Update:", data);
        });

        await new Promise<void>((resolve, reject) => {
          stream.write({
            accounts: {
              tokenProgram: {
                owner: ["TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA"],
                account: [],
                filters: [],
              },
            },
            slots: {},
            transactions: {},
            blocks: {},
            blocksMeta: {},
            entry: {},
            accountsDataSlice: [],
            commitment: CommitmentLevel.PROCESSED,
          }, (err) => err ? reject(err) : resolve());
        });
        ```

        Rust, Go, and Python examples: [yellowstone-grpc/examples](https://github.com/rpcpool/yellowstone-grpc/tree/master/examples).
      </Tab>
      <Tab title="Whirligig">
        Connect over WebSocket using any standard client. No Triton-specific SDK required.

        ```typescript
        import WebSocket from "ws";

        const ws = new WebSocket(
          "wss://<your-endpoint>.mainnet.rpcpool.com/<your-token>/whirligig"
        );

        ws.on("open", () => {
          ws.send(JSON.stringify({
            jsonrpc: "2.0",
            id: 1,
            method: "accountSubscribe",
            params: [
              "SysvarC1ock11111111111111111111111111111111",
              { commitment: "processed", encoding: "base58" },
            ],
          }));
        });

        ws.on("message", (data) => {
          console.log("Update:", JSON.parse(data.toString()));
        });
        ```

        Whirligig speaks the standard Solana WebSocket API plus an extended `transactionSubscribe` method. Full method reference: [Whirligig WebSocket API](/solana/streaming/whirligig/overview).
      </Tab>
      <Tab title="Fumarole">
        Fumarole adds a persistent subscriber on top of Dragon's Mouth. Connect to a regional endpoint (`ams.rpcpool.com` for Europe, `nyc.rpcpool.com` for the US) and pick a subscriber name.

        ```typescript
        import { FumaroleClient } from "@triton-one/yellowstone-fumarole-client";

        const client = await FumaroleClient.connect({
          endpoint: "https://ams.rpcpool.com",
          xToken: "<your-token>",
        });

        const session = await client.dragonsmouthSubscribe("my-subscriber", {
          transactions: {
            all: { vote: false, failed: false },
          },
        });

        for await (const event of session.source) {
          console.log("Update:", event);
        }
        ```

        The first time you call `dragonsmouthSubscribe` with a new subscriber name, Fumarole creates the persistent subscriber. Reconnect with the same name and you resume from where you left off. Rust example and full configuration: [yellowstone-fumarole](https://github.com/rpcpool/yellowstone-fumarole).
      </Tab>
      <Tab title="Old Faithful streams">
        Old Faithful uses the same gRPC dialect as Dragon's Mouth. The streaming methods are `StreamTransactions` and `StreamBlocks`, replaying historical data from any starting slot.

        ```typescript
        import { OldFaithfulClient } from "@triton-one/yellowstone-grpc";

        const client = new OldFaithfulClient(
          "https://<your-old-faithful-endpoint>",
          "<your-token>"
        );

        const stream = await client.streamBlocks({
          startSlot: 100_000_000,
          endSlot: 100_000_100,
        });

        for await (const block of stream) {
          console.log("Block:", block.slot);
        }
        ```

        Live and historical pipelines look identical to your client code, so anything you build for Dragon's Mouth adapts to Old Faithful with minimal changes. Full method list: [Old Faithful gRPC methods](/solana/streaming/old-faithful-streams).
      </Tab>
    </Tabs>
  </Step>

  <Step title="Test your stream">
    Run your code and walk through this checklist:

    1. **Confirm the connection.** A "subscribed" or "connected" log message should appear within a second of starting.
    2. **Watch for events.** Matching events should start flowing within 1-2 slots (roughly 800 ms).
    3. **Verify your filter.** If nothing arrives after 5 seconds, your filter is probably too narrow. Widen it (e.g. all transactions instead of one program), then tighten back once you see data flowing.
    4. **Test reconnection (optional).** Drop your network briefly and confirm your client reconnects and resumes.

    **Expected output**

## FAQs

<AccordionGroup>
  <Accordion title="My stream connects but no events are flowing">
    The most common cause is a filter that's too narrow. Try widening it (subscribe to all transactions or all token-program account writes) to confirm data is reaching you, then tighten back to what you actually need. Also check your commitment level: `processed` shows everything as soon as the validator sees it, while `confirmed` and `finalized` add buffering.
  </Accordion>

  <Accordion title="I'm getting 401 or 403 errors">
    Verify your endpoint URL and secret token from the [customer dashboard](https://customers.triton.one). For Whirligig, the token is part of the URL: `wss://<endpoint>.mainnet.rpcpool.com/<token>/whirligig`. For gRPC services, the token is passed as the `x-token` metadata header, not in the URL. If you've recently configured allowed origins, double-check your origin matches what's whitelisted.
  </Accordion>

  <Accordion title="My stream keeps disconnecting">
    Networks drop. Production clients should implement reconnect-and-resubscribe logic with exponential backoff. For Dragon's Mouth, you can resume from your last-seen slot using the `from_slot` field on `SubscribeRequest`. For Fumarole, reconnect with the same persistent-subscriber name and the cursor server-side picks up where you left off.
  </Accordion>

  <Accordion title="Events feel slower than expected">
    Three things to check. First, your commitment level: `processed` is fastest, `confirmed` and `finalized` add latency. Second, geographic distance: connect from a backend close to our streaming clusters. Third, your processing speed: if your event handler can't keep up, the server-side queue backs up and you fall behind.
  </Accordion>

  <Accordion title="Memory grows over time">
    Your handler is processing events slower than they arrive. Filter more aggressively to reduce volume, parallelise your handler across workers, or move heavy processing to a background queue and keep the stream loop minimal.
  </Accordion>

  <Accordion title="Do I need to send keepalive pings?">
    Sometimes. Some load balancers and NATs close idle TCP connections after a minute or two. If you see disconnections after periods of low traffic, send a periodic ping. Dragon's Mouth gRPC accepts a `ping` field on the subscribe request; Whirligig accepts `{"jsonrpc":"2.0","method":"ping"}`. The server returns `pong` you can use to confirm liveness.
  </Accordion>
</AccordionGroup>
