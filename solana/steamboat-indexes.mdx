Steamboat is Triton One's high-performance backend for `getProgramAccounts` (gPA) queries. Instead of scanning the entire chain state on every request, Steamboat serves gPA queries from a dedicated database populated with indexes tuned precisely to your application's query patterns. The result is a dramatic reduction in query latency — in benchmarks, filtered `getProgramAccounts` calls for the Stake program dropped from roughly 1700 ms to roughly 30 ms. Because Steamboat answers standard JSON-RPC calls, your application code doesn't change at all.

## How it works

Enabling Steamboat requires deploying the Steamboat Geyser plugin on your dedicated node. The plugin streams on-chain account updates into a separate indexer database in real time, keeping the index current as the chain progresses. When your application sends a `getProgramAccounts` request with `memcmp` or other filters, the request is answered from this database rather than from the full account state on the node.

The indexes must be configured to match your actual query patterns. Generic indexes don't provide the same speedup as indexes built for your specific filter offsets and byte patterns.

## Index configuration

Triton One offers two approaches to building the right indexes for your workload:

<Note>
  Indexes are optimized for your existing traffic patterns. If your query patterns change significantly — new filter offsets, new programs, new byte patterns — the indexes may need to be refreshed. Contact support to request an update.
</Note>

## Example: filtered getProgramAccounts

The request format is identical to standard Solana JSON-RPC. Steamboat intercepts the request server-side — you don't add any special parameters or headers.

```bash
curl -X POST https://your-endpoint.mainnet.rpcpool.com/your-token \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "getProgramAccounts",
    "params": [
      "Stake11111111111111111111111111111111111111112",
      {
        "filters": [
          { "dataSize": 200 },
          {
            "memcmp": {
              "offset": 44,
              "bytes": "YourVoteAccountAddressBase58Here"
            }
          }
        ],
        "encoding": "base64"
      }
    ]
  }'
```

When Steamboat has an index that covers these exact filter parameters, it answers the query from the database in milliseconds. Without Steamboat, this query would require a full account-state scan.

## Limitation: SPL Token Program

Steamboat does **not** support `getProgramAccounts` queries for the standard SPL Token Program (`TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA`). The Agave validator software already includes built-in secondary indexes for token accounts, so performance for SPL token gPA is already well-optimized at the node level. Steamboat targets custom program accounts where those built-in optimizations don't exist.

<Tip>
  For token account queries, use `getTokenAccountsByOwner` for owner lookups, or the [Digital Assets API](/solana/digital-assets-api) for richer filtering including compressed NFTs and Token-2022.
</Tip>

## Availability and how to enable it

Steamboat is available for **dedicated node customers only**. It requires a custom setup, additional hardware resources on your node, and an index configuration step tailored to your application.

To get started, contact Triton One support via the chat in your [customer dashboard](https://customers.triton.one). Describe your program IDs and the filter patterns your application uses for `getProgramAccounts`, and the team will work with you on the index configuration.
