Photon is the core indexer for Light Protocol, the infrastructure layer behind ZK Compression on Solana. ZK Compression lets programs store state in compressed form on-chain, dramatically reducing the cost of creating and maintaining large numbers of accounts — but that compressed state requires a specialized indexer to query, since standard Solana RPC methods can't read it. Triton One runs a managed Photon instance and exposes its API through your existing endpoint URL, giving you access to compressed account data without running your own indexer.

## Why Photon exists

Light Protocol compresses state using zero-knowledge proofs, storing only a small on-chain fingerprint while keeping the actual account data in a structured off-chain index. To read a compressed account's balance, retrieve a proof, or look up a compressed token holding, you need to query the Photon indexer — not the standard Solana account state. The Photon API extends the standard JSON-RPC interface with additional methods for all of these operations.

<Note>
  Light Protocol data is excluded from Triton One's standard gRPC (Dragon's Mouth) streams due to the volume of compression-related events it generates. Use the Photon API methods described on this page to access ZK Compression data instead.
</Note>

## Accessing Photon on Triton One

Photon is available on shared endpoints and can also be deployed as a dedicated instance for high-demand applications. Your Triton One endpoint already has Photon integrated — call any of the `getCompressed*` methods listed below against your standard endpoint URL.

```bash
curl -X POST https://your-endpoint.mainnet.rpcpool.com/your-token \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "getCompressedAccount",
    "params": {
      "address": "YourCompressedAccountAddressHere"
    }
  }'
```

For a dedicated Photon instance with guaranteed resources, contact Triton One support via your [customer dashboard](https://customers.triton.one).

## Available API methods

The Photon API extends the Solana JSON-RPC specification. All methods follow the standard JSON-RPC 2.0 request format. Full parameter documentation is available in the [ZK Compression JSON-RPC reference](https://www.zkcompression.com/developers/json-rpc-methods).

### Account queries

| Method | Description |
|--------|-------------|
| `getCompressedAccount` | Retrieve a compressed account by its address or hash. |
| `getCompressedBalance` | Retrieve the balance of a compressed account. |
| `getCompressedBalanceByOwner` | Retrieve the total compressed balance across all accounts owned by a specific address. |
| `getCompressedAccountsByOwner` | Retrieve all compressed accounts owned by a specific address, paginated. |
| `getMultipleCompressedAccounts` | Retrieve multiple compressed accounts by their addresses or hashes in a single request. |

### Token queries

| Method | Description |
|--------|-------------|
| `getCompressedTokenAccountBalance` | Retrieve the balance of a compressed token account. |
| `getCompressedTokenBalancesByOwnerV2` | Retrieve all compressed token balances owned by a specific address, paginated. |
| `getCompressedMintTokenHolders` | Retrieve owner balances for a compressed mint in descending order. |
| `getCompressedTokenAccountsByDelegate` | Retrieve all compressed token accounts delegated to a specific address, paginated. |

### Proofs and validity

| Method | Description |
|--------|-------------|
| `getCompressedAccountProof` | Retrieve the proof that the compression program uses to verify the validity of a compressed account. |
| `getMultipleCompressedAccountProofs` | Retrieve validity proofs for multiple compressed accounts in a single request. |
| `getMultipleNewAddressProofs` | Retrieve proofs that new addresses are not already taken and can be created. |
| `getValidityProof` | Retrieve a single ZK proof used by the compression program to verify account validity and confirm new addresses can be created. |

### Transaction and signature queries

| Method | Description |
|--------|-------------|
| `getTransactionWithCompressionInfo` | Retrieve transaction details along with associated compression information. |
| `getCompressionSignaturesForAccount` | Retrieve transaction signatures that opened or closed a compressed account, paginated. |
| `getCompressionSignaturesForAddress` | Retrieve transaction signatures that opened or closed a compressed account for a specific address, paginated. |
| `getCompressionSignaturesForOwner` | Retrieve transaction signatures that modified a compressed account of a specific owner, paginated. |
| `getCompressionSignaturesForTokenOwner` | Retrieve transaction signatures that modified a compressed token account of a specific owner, paginated. |
| `getLatestCompressionSignatures` | Retrieve signatures of the most recent compression transactions, paginated. |
| `getLatestNonVotingSignatures` | Retrieve signatures of the latest non-voting transactions. |

### Indexer status

| Method | Description |
|--------|-------------|
| `getIndexerSlot` | Retrieve the slot number of the latest block indexed by Photon. Use this to check how far behind the indexer is relative to the chain tip. |
| `getIndexerHealth` | Retrieve the indexer status. Returns `ok` when the indexer is not stale. |

## Example requests

<CodeGroup>

```json getCompressedAccount
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "getCompressedAccount",
  "params": {
    "address": "YourCompressedAccountAddressBase58Here"
  }
}
```

```json getCompressedTokenBalancesByOwnerV2
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "getCompressedTokenBalancesByOwnerV2",
  "params": {
    "owner": "YourOwnerAddressBase58Here",
    "limit": 50,
    "cursor": null
  }
}
```

```json getValidityProof
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "getValidityProof",
  "params": {
    "hashes": ["CompressedAccountHashBase58Here"],
    "newAddresses": []
  }
}
```

```json getIndexerHealth
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "getIndexerHealth",
  "params": []
}
```

</CodeGroup>
