Triton One's streaming suite gives you real-time access to Solana on-chain data at every level of the stack. Whether you're building a high-frequency trading bot that needs raw speed, a frontend dApp that needs responsive account updates, or a compliance system that needs guaranteed delivery, there's a streaming product built for your requirements. Streaming data from Solana requires a high-bandwidth connection and a capable client environment—frequent disconnections are a sign of an under-resourced setup, not a server problem.

## Streaming products at a glance

<CardGroup cols={2}>
  <Card title="Dragon's Mouth gRPC" icon="bolt" href="/streaming/dragons-mouth-grpc">
    The fastest path to real-time on-chain data. A Geyser-fed gRPC interface that streams account writes, transactions, entries, blocks, and slot notifications directly to your backend.

    **Best for:** High-frequency trading bots, MEV searchers, backend services, any system where milliseconds matter.

    **Key advantage:** Intra-slot updates deliver data up to 400ms faster than standard WebSockets.

    **Note:** gRPC is not supported in web browsers. This is a backend-only interface.
  </Card>
  <Card title="Whirligig WebSockets" icon="wifi" href="/streaming/whirligig-websockets">
    A high-performance, drop-in replacement for Solana's standard WebSocket API, built on top of Dragon's Mouth gRPC streams.

    **Best for:** Web3 frontends, real-time user interfaces, teams upgrading existing WebSocket-based apps.

    **Key advantage:** Same intra-slot speed as gRPC but over a browser-compatible WebSocket connection.

    **Note:** Supports browsers and any existing Solana WebSocket client.
  </Card>
  <Card title="Fumarole" icon="database" href="/streaming/fumarole">
    A persistent, "never miss an event" streaming system for applications where complete data delivery is critical.

    **Best for:** Accounting systems, compliance tools, analytics platforms, and any application requiring a verifiable event history.

    **Key advantage:** Reconnect and automatically backfill missed events. Supports horizontal scaling via consumer groups.

    **Note:** Currently in limited beta.
  </Card>
  <Card title="Vixen" icon="code" href="/streaming/vixen-program-streams">
    A modular framework for building program-aware, real-time Solana data pipelines on top of Dragon's Mouth gRPC.

    **Best for:** Teams building indexers, analytics pipelines, or event-driven applications for specific Solana programs.

    **Key advantage:** Ships with parsers for Jupiter, Raydium, Meteora, Pump.fun, and many more—no deserialization logic required.

    **Note:** Open source, self-hostable, Prometheus metrics included.
  </Card>
</CardGroup>

## Choosing the right option

| | Dragon's Mouth | Whirligig | Fumarole | Vixen |
|---|---|---|---|---|
| Protocol | gRPC | WebSocket | gRPC | gRPC |
| Browser support | No | Yes | No | No |
| Intra-slot updates | Yes | Yes | No | Via Dragon's Mouth |
| Guaranteed delivery | No | No | Yes | No |
| Reconnect & backfill | Limited (`from_slot`) | No | Yes | No |
| Program-level parsing | No | No | No | Yes |
| Horizontal scaling | No | No | Yes (consumer groups) | Yes |
| Status | GA | GA | Limited beta | GA |

## Performance requirements

<Warning>
Solana's full-chain feed can spike to 1.3–1.8 Gbps. If you subscribe to broad filters with Dragon's Mouth, your client environment must keep up. See the [Streaming Troubleshooting guide](/support/streaming-troubleshooting) for guidance before opening a support ticket.
</Warning>

### Troubleshooting checklist

Before contacting Triton support about disconnects, verify the following:

- Your subscriber host has at least **5 Gbps** of network capacity. Cloud instances are often capped at 1 Gbps by default.
- Round-trip latency from your subscriber to the Triton endpoint is **≤ 50 ms**. Measure from the same machine that runs your client.
- **Zstd compression** is enabled. Without it, bandwidth requirements increase significantly during traffic spikes.
- **Adaptive window size** is set to `true` so the client can adjust flow-control automatically.
- You are **not** running your subscriber inside an AWS Lambda or similar serverless function. These leave many open connections on the server and degrade service.
- You are **not** using vanilla Node.js. Standard Node.js is too slow for the Solana data volume. Use Rust, Go, or the NAPI-accelerated `@triton-one/yellowstone-grpc` TypeScript client.
- You've tested stream capacity with the `client-ubuntu` binary using `--http2-adaptive-window true --compression zstd --stats`. A healthy setup outputs a ping every 10 seconds with 60–80 Mbps throughput.

<Tip>
If your workload prioritizes data completeness over absolute minimum latency—for example, accounting, analytics, or indexing—consider using Fumarole instead of raw Dragon's Mouth gRPC.
</Tip>
