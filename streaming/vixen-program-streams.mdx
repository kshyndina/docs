Vixen is a modular, open-source framework for building program-aware, real-time Solana data pipelines. Instead of receiving raw account blobs and writing your own deserialization logic for every program you care about, Vixen lets you plug in a parser and immediately receive structured, actionable data. It listens to Dragon's Mouth gRPC streams, routes program-specific changes through composable parsers, and delivers ready-to-use outputs to your application—whether that's a database write, an API call, or a downstream gRPC stream to your own clients.

## Why use Vixen

Traditional Solana infrastructure requires deep protocol knowledge, custom parsing for every program, and significant infrastructure to handle the data volume. Vixen changes the model:

| Benefit | How Vixen delivers it |
|---|---|
| Cost efficiency | Share a single Dragon's Mouth stream among multiple pipelines. Process only the programs you need. |
| Operational simplicity | Lightweight and dependency-free. Run it in your own infra, Docker, or Kubernetes. |
| Observability | Real-time metrics via Prometheus: lag, throughput, and error rates out of the box. |
| Composability | Reusable parser crates handle complex cross-program interactions, including CPIs. |
| Stream-ready outputs | Serve parsed data directly to clients over your own gRPC interfaces. |

## Quick start

The example below sets up a pipeline that listens to Token Program account and instruction updates and logs them using Prometheus metrics.

```rust
use yellowstone_vixen::Pipeline;
use yellowstone_vixen_parser::token_program::{AccountParser, InstructionParser};
use yellowstone_vixen_yellowstone_grpc_source::YellowstoneGrpcSource;

#[derive(Debug)]
pub struct Logger;

impl<V: std::fmt::Debug + Sync> vixen::Handler<V> for Logger {
    async fn handle(&self, value: &V) -> vixen::HandlerResult<()> {
        tracing::info!(?value);
        Ok(())
    }
}

fn main() {
    yellowstone_vixen::Runtime::builder()
        .source(YellowstoneGrpcSource::new())
        .account(Pipeline::new(AccountParser, [Logger]))
        .instruction(Pipeline::new(InstructionParser, [Logger]))
        .metrics(yellowstone_vixen::metrics::Prometheus)
        .commitment_level(yellowstone_vixen::CommitmentLevel::Confirmed)
        .build(config)
        .run();
}
```

Run with your config file:

```bash
RUST_LOG=info cargo run -- --config ./Vixen.toml
```

## Program Data Streams (hosted Vixen)

If you want parsed program data without running Vixen yourself, Triton One provides a hosted Program Data Streams service. Install the TypeScript SDK and subscribe to any supported program with a few lines of code:

```bash
npm install @triton-one/vixen-stream
```

```typescript
import {
  ProgramStreamsServiceClient,
  ProgramUpdateType,
  credentials,
  createCallCredentials,
  ProgramAddress,
} from "@triton-one/vixen-stream";

const creds = credentials.createSsl();
const callCredentials = createCallCredentials("<token>");
const combinedCredentials = credentials.combineChannelCredentials(
  creds,
  callCredentials
);

const client = new ProgramStreamsServiceClient("<endpoint>", combinedCredentials);

// Subscribe to account and instruction updates for the Token program
const stream = client.Subscribe({
  program: ProgramAddress.Token,
});

stream.on("data", function (update: ProgramUpdateType<ProgramAddress.Token>) {
  console.log(update);
});

stream.on("end", () => console.log("end"));
stream.on("error", (e: Error) => console.log("error: ", e));
```

<Note>
Program Data Streams is currently in beta. You need a Triton One authentication token to connect. Contact Triton support to receive one.
</Note>

## Observability

To run Prometheus locally and scrape Vixen metrics:

```bash
sudo docker-compose up
```

Then open `http://localhost:9090` to explore lag, throughput, and error rate metrics.
