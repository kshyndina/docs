Fumarole is Triton One's persistent streaming system for applications that cannot afford to miss a single on-chain event. While Dragon's Mouth gRPC gives you the lowest possible latency, Fumarole gives you reliability: it stores historical state, lets you reconnect and automatically resume where you left off, and merges data from multiple downstream Solana nodes so your stream stays healthy even when individual nodes restart or are upgraded. If you're building accounting systems, compliance tools, or analytics platforms that need a complete and verifiable event history, Fumarole is the right choice.

<Note>
Fumarole is currently in limited beta. Contact your Triton customer support channel to request access.
</Note>

## What Fumarole provides

<CardGroup cols={3}>
  <Card title="High availability" icon="server">
    Fumarole collects data from multiple downstream Solana nodes and merges them into a single stream. If one node restarts or is upgraded, your stream continues uninterrupted.
  </Card>
  <Card title="Persistence" icon="database">
    Fumarole stores historical state. If your client goes down—for minutes or hours—you can reconnect and resume from the exact point you left off, with no gaps in your data.
  </Card>
  <Card title="Parallel replay" icon="forward">
    When catching up after downtime, Fumarole replays buffered Geyser data in parallel, letting you backfill quickly without processing events sequentially.
  </Card>
</CardGroup>

## Use cases

Fumarole is the right streaming option when:

- Your application needs a **complete event history** with no gaps (accounting, compliance, auditing)
- You need to **survive client downtime** without losing data
- You want **horizontal scaling** by distributing work across multiple consumers using consumer groups
- You're running **analytics or indexing workloads** where data completeness matters more than absolute minimum latency

<Tip>
If you already use Dragon's Mouth and are primarily concerned with latency, stay on Dragon's Mouth. If you're experiencing data loss during client restarts or need guaranteed delivery semantics, migrate to Fumarole.
</Tip>

## Migrating from Dragon's Mouth

If you already have code built against Dragon's Mouth gRPC, integrating Fumarole requires minimal changes. Fumarole uses the same data types as Dragon's Mouth, so your existing deserialization and processing logic carries over without modification.

The main differences are:

1. **Consumer group management** — Fumarole introduces the concept of consumer groups, which you need to create and manage. Consumer groups are how Fumarole tracks your stream position and enables horizontal scaling.
2. **Subscribe request format** — The subscribe request is slightly different from Dragon's Mouth's `SubscribeRequest`. See the [GitHub repository](https://github.com/rpcpool/yellowstone-fumarole) for the full API reference and migration examples.

<Note>
Because Fumarole uses the same types as Dragon's Mouth, switching does not require rewriting your parsing or business logic—only the connection and subscription setup changes.
</Note>
